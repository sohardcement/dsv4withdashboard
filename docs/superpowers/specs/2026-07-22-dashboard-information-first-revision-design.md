# DS4 Dashboard「信息优先」修订设计

## 状态

用户已否决原 B1「流明墙」的巨数幕墙实现，并批准本修订方向：保留浅色黑白灰、悬浮毛玻璃和明确交互反馈，但信息阅读必须绝对优先。

## 问题判定

原实现同时放置五个幽灵巨数，并通过负左边距把玻璃控制柱压入主墙区。这导致：

- 背景数值与真实读数重叠，主次层级消失；
- 右侧控制柱裁切或遮挡调用状态；
- 页面外缘出现无意义深色留白，内容像被放在海报画框中；
- 动效和空间感没有服务于排障与读数。

本次不通过降低透明度或微调间距修补，而是移除问题结构。

## 视觉方向

页面定位为高端实时控制台，而不是数据海报：

- 整个可视区域使用连续的浅灰白底，不出现深色画框或大面积空白边；
- 只保留一层极淡、无文字的灰阶环境光，不包含任何巨型数字、水印或装饰性字符；
- 玻璃只用于右侧操作列及少量控件，作为层次而不是内容遮罩；
- 墨黑承担主要读数、标题和主操作；红绿仅用于成功/失败状态。

## 布局

### 桌面（>= 981px）

- 顶部保留品牌、模式切换与连接状态；
- 主内容为严格两列：左侧数据区 `minmax(0, 1fr)`，右侧玻璃操作列 `400px`，列间距至少 `24px`；
- 不允许任何负边距、跨列重叠、裁切右栏或让玻璃列覆盖数据区；
- 左侧首行是一个清晰的主吞吐读数（解码速度），其余预填充、KV 命中、上下文、队列和运行阶段以正常字号组成对齐网格；
- 主机资源与指标区组成紧凑左侧信息栈（间距约 18px），不因右侧检查器更高而被推离首屏；
- 右侧玻璃列完整容纳调用筛选、调用电报与请求检查器。

### 窄桌面与移动端

- 981–1307px：右侧列最小 `360px`，指标切换为三列以保持两列不重叠；
- <= 980px：切换为单列，玻璃列进入正常文档流；
- 390px：单列、无页面横滚，只有调用表容器可横滚。

## 动效

- 数值变化保留方向滚动，且只作用于真实数值；
- 选中调用行保留短距离横移和墨线；
- 模式切换与按钮保留轻微淡入/按压反馈；
- 环境光可保留极慢位移，但不改变文字、布局或透明度；
- 每项互动动画最长 240ms（数值滚动可保持既有 420ms），reduced-motion 与 stale 状态立即静止；
- 不再使用占据主体视觉的循环装饰动画。

## 验收标准

1. 1440×900 截图中，任一真实读数不得与装饰文字或右栏重叠；
2. 右栏 `left >= 左栏 right + 24px`，且完整位于 viewport 内；
3. 页面不渲染 `.wall-mirror` 或任何巨型数字背景节点；
4. 页面根背景覆盖 viewport，不出现用于装饰的深色外框；
5. 1440、1024、390px 的浏览器截图和既有功能回归均通过；
6. 调用筛选、请求检查器、KV、上下文、离线与 reduced-motion 语义不变。

## 实施范围

- `ds4_server.c`：仅调整内嵌 Dashboard 的 CSS、必要 DOM 和对应行为；
- `tests/dashboard_ui_test.js`：将旧的幕墙断言替换为无重叠、无巨数节点、右栏边界和响应式断言；
- `README.md`：将产品视觉描述修正为信息优先的浅色玻璃控制台；
- 不改动状态 API、推理逻辑、KV/上下文后端契约或其他已有未提交改动。
